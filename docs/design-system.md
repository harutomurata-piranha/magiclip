# MagiClip デザインシステム

**コンセプト: 魔法のように動画をつくれる。**

ここでいう魔法とは、装飾のことではない。
**手数が異常に少ないのに、期待を超えたものが返ってくる**という体験のこと。

だから MagiClip の UI は、魔法を「描く」のではなく「起こす」。
きらびやかな装飾（絵文字・グラデーション・光る枠）は、むしろ手品の種明かしのように安っぽく見え、
「AI が適当に作った」印象に直結する。**種を見せず、結果だけを鮮やかに出す**のが本物の魔法。

このドキュメントは、UI を書くときに毎回参照する唯一の基準。
迷ったら「増やす」ではなく「減らす」を選ぶ。

---

## 1. デザイン原則

### 原則 1: 魔法は装飾ではなく、手数の少なさで表現する
魔法らしさの正体は「こんなに簡単なのに、こんなものが出てきた」という落差。

- ✅ OK: アップロード画面にあるのは、ファイル選択と「作成する」だけ
- ✅ OK: 完成画面を開いた瞬間、動画が自動で再生されている（説明を読ませない）
- ❌ NG: 「✨ 魔法をかける」というラベル。**言葉で魔法を主張するのは、魔法が起きていない証拠**
- ❌ NG: 設定項目・オプション・確認ステップを増やす（1 つ増えるごとに魔法は消える）

### 原則 2: 主役はユーザーの素材。UI は舞台であって出演者ではない
画面で最も色鮮やかなものが、常にユーザーの動画であること。

- ✅ OK: 無彩色に近い画面に、動画とサムネイルだけが色を持つ
- ❌ NG: 動画の周りをグラデーション・影・色付きカードで囲む
- ❌ NG: 画面の色数がユーザーの動画より多い

### 原則 3: 「見せ場」は 1 画面に 1 つだけ作る
すべてが主張する画面に、魔法の瞬間は生まれない。落差を作るために、他は静かにする。

- ✅ OK: 完成画面の見せ場は「動画そのもの」。CTA は「ダウンロード」1 つで、他は secondary
- ✅ OK: 生成中の見せ場は「進捗」。他の情報は最小限
- ❌ NG: 同じ大きさ・同じ色のボタンが 3 つ横に並ぶ
- ❌ NG: 見出しもボタンもバッジも全部が色付きで主張している

### 原則 4: 言葉は指示。説明で UI の不足を埋めない
MagiClip の価値は「考えなくていい」こと。文章を読ませた時点で負け。

- ✅ OK: ボタンは「作成する」「ダウンロード」「作り直す」。補足なしで意味が通る
- ❌ NG: 「✨ 魔法をかける」「完成しました 🎉」「簡単にできます!」
- ❌ NG: ボタンの下に 2 行の使い方説明を置く（説明が要るなら UI を直す）
- 感嘆符・煽り・絵文字は使わない。淡々と、正確に。

### 原則 5: 待ち時間と失敗こそ、信頼が決まる場所
魔法が数分かかる以上、その間の見せ方が体験の質を決める。裏で何が起きているかは隠さない。

- ✅ OK: 進捗バー＋いまの工程名＋残り時間。失敗時は原因と次の一手
- ❌ NG: くるくる回るだけのスピナー。「エラーが発生しました」だけ
- 空・処理中・エラー・完了の 4 状態を、必ず設計してから実装する

### 原則 6: 独自性は「言葉で編集する」ことに宿る
他の編集ツールは映像（クリップ・タイムライン）が主役。MagiClip は**言葉が主役**。
この違いが唯一の独自性であり、UI で最も強く出すべき点。

- ✅ OK: 編集画面の中心は「文字起こしの一覧」。文字を消すと、その映像も消える
- ✅ OK: タイムライン・トラック・波形といった従来の編集 UI を持ち込まない
- ❌ NG: 映像のタイムラインを主役に据える（＝ただの編集ソフトになり、独自性が消える）

## 2. デザイントークン

**ここに無い値は使わない。** 追加したくなったら、まず既存で代用できないか考える。

### 2.1 Color

ライト基調。グレーは 1 系統（わずかに青みのニュートラル）。アクセントは**紺に近いブルー 1 色のみ**。

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` | `#ffffff` | ページ背景 |
| `--surface` | `#f7f8fa` | 面（カード・入力欄の背景） |
| `--line` | `#e4e7ec` | 境界線・区切り |
| `--text` | `#1a1d23` | 本文・見出し |
| `--text-muted` | `#5f6673` | 補足・ラベル（本文より弱いが読める濃さ） |
| `--accent` | `#1e3a8a` | 主 CTA・選択状態・進捗（**この 1 色だけ**） |
| `--accent-weak` | `#eef2ff` | アクセントの薄い面（選択行の背景など） |
| `--danger` | `#b42318` | エラー・破壊的操作 |
| `--success` | `#067647` | 完了 |

**禁止**:
- アクセントを 2 色使うこと（旧 `--brand2` シアンは廃止）
- 同系色の微妙な違いを増やすこと（旧 紫 4 系統の再発）
- グラデーション（後述）

**ブランドカラー（紫）の扱い**: ロゴの紫 `#7C3AED` は UI の色ではなく**ブランドの色**。使ってよいのは次の 4 箇所だけ。

1. ロゴマーク（ヘッダー）
2. ファビコン
3. 動画に焼き込む透かし
4. **完成の瞬間**（後述の「魔法の瞬間」。1 セッションに 1 度だけ現れる）

ボタン・リンク・バッジ・枠線・背景には使わない。**日常的に出てこないからこそ、完成時に効く。**

### 2.2 Spacing

**4px グリッド**。以下の 7 段階のみ。

| トークン | 値 | 目安 |
|---|---|---|
| `--s1` | `4px` | 密接する要素の間 |
| `--s2` | `8px` | ラベルと入力欄 |
| `--s3` | `12px` | 要素内の余白 |
| `--s4` | `16px` | 標準の余白・カード内側 |
| `--s5` | `24px` | 要素グループの間 |
| `--s6` | `32px` | セクションの間 |
| `--s7` | `48px` | ページ上下の余白 |

半端な値（2, 3, 5, 6, 7, 10, 14, 15, 18, 22, 26, 30, 50px）は使わない。

### 2.3 Typography

サイズ **5 段階**、ウェイト **3 種**のみ。

| トークン | 値 | 用途 |
|---|---|---|
| `--fs-xs` | `12px` | 補助情報（タイムコード・注記） |
| `--fs-sm` | `14px` | 補足・ラベル |
| `--fs-base` | `16px` | 本文・入力欄（**入力欄は 16px 未満にしない**: iOS の自動ズーム防止） |
| `--fs-lg` | `20px` | 小見出し |
| `--fs-xl` | `28px` | ページ見出し |

ウェイト: `400`（本文） / `600`（見出し・ラベル） / `700`（主 CTA のみ）
行間: 本文 `1.7` / 見出し `1.3`

### 2.4 Radius

**2 種のみ**。

| トークン | 値 | 用途 |
|---|---|---|
| `--r-sm` | `8px` | ボタン・入力欄・タグ |
| `--r-md` | `12px` | カード・パネル・動画 |

`999px`（全円）は、タグ・バッジなど**文字を囲む小要素のみ**例外的に許可。

### 2.5 Elevation（影）

**2 段階まで**。影で階層を作らず、まず境界線と余白で分ける。

| トークン | 値 | 用途 |
|---|---|---|
| （既定） | なし | ほとんどの要素。境界線 `--line` で区切る |
| `--e1` | `0 1px 2px rgba(16,24,40,.06)` | 浮いていることを示す面（ドロップダウン等） |
| `--e2` | `0 8px 24px rgba(16,24,40,.12)` | 画面を覆う要素（モーダル・トースト）のみ |

## 3. コンポーネント規約

### Button
| バリアント | 見た目 | 使い方 |
|---|---|---|
| `primary` | `--accent` 背景 / 白文字 / `--r-sm` | **1 画面に 1 つだけ**。その画面で最もしてほしい操作 |
| `secondary` | 白背景 / `--line` 枠 / `--text` | 併置される次点の操作 |
| `ghost` | 背景なし / `--text-muted` | 戻る・キャンセルなど後退の操作 |
| `danger` | `--danger` 文字（枠のみ） | 削除など取り返しのつかない操作 |

- 高さは 44px 以上（指で押せる）。幅は内容なり。スマホでは主 CTA のみ全幅可
- ラベルは動詞で始める短い指示（「ダウンロード」「作り直す」）。絵文字を入れない

### Input / Textarea / Select
- 背景 `--surface` / 枠 `--line` / 角丸 `--r-sm` / 文字 `--fs-base`
- フォーカス時は枠を `--accent` に。影は付けない
- ラベルは入力欄の上に `--fs-sm` `--text-muted`。プレースホルダーをラベル代わりにしない

### Card
**「独立して操作できるまとまり」にだけ使う。**（例: 料金プラン、編集画面の 1 シーン）

- 背景 `--bg` / 枠 `--line` / 角丸 `--r-md` / 内側 `--s4`
- 影は付けない
- ❌ NG: 単に情報を置きたいだけでカードで囲む。見出し＋本文は素のままでよい

### Modal
- 中央 / 最大幅 560px / 角丸 `--r-md` / 影 `--e2` / 背景オーバーレイ `rgba(16,24,40,.4)`
- 破壊的操作の確認に使う。情報表示だけのために出さない

### Toast
- 画面下（スマホ）／右下（PC）。`--e1`。3 種: 完了 `--success` / エラー `--danger` / 情報 `--text`
- 4 秒で自動的に消える。エラーは消さず、閉じるまで残す

### 空状態
「空白」で終わらせない。**必ず 3 点セット**にする。

1. 何が無いかの 1 行（`--text`）
2. なぜ / どうすれば良いかの 1 行（`--fs-sm` `--text-muted`）
3. **次の操作の primary ボタン 1 つ**

### ローディング
- **不定のスピナーだけで済ませない**。処理が数秒を超えるなら、進捗・工程名・残り時間を出す
- 秒単位の推定は丸める（「残り約 2 分」）。超過したら「もうしばらくかかります」に切り替え、マイナス表示しない
- 画面を閉じてよいかを明記する

### エラー表示
**「何が起きたか」＋「どうすれば直るか」＋「次の操作」**を必ず揃える。

- ❌ NG: 「エラーが発生しました」
- ✅ OK: 「この動画からは編集を作れませんでした。音声が入っていないか、短すぎる可能性があります。」＋「別の動画を選ぶ」ボタン

## 4. 禁止事項

- **装飾的な絵文字**。アイコンが必要なら SVG アイコンに統一する（ユーザー生成コンテンツは除く）
- **グラデーション**（背景・文字・ボタン・進捗すべて）。単色を使う
- **`--e2` を超える影**、および影の常用
- **意味のないカード**。独立して操作できないものは囲まない
- **煽り・感嘆符・「〜しましょう!」「簡単に〜できます!」**。UI の文言は指示に徹する
- **意味のない中央揃え**。中央揃えは 1〜2 行の見出しまで。本文・リスト・フォームは左揃え
- **冗長な補足テキスト**。説明が要るなら UI 側を直す
- **アクセント 2 色目の追加**
- **4px グリッドから外れた余白**
- **トークンにない値のハードコード**、およびテンプレートへのインライン `style`

## 5. UX チェックリスト（各画面で満たす）

1. 初見のユーザーが「次にすべき操作」を 3 秒で特定できるか
2. 空状態（0 件）が設計されているか
3. 処理中に「何が起きているか / あとどれくらいか / 中断できるか」が分かるか
4. エラーに「何が失敗したか / どう直すか」が書かれているか
5. 結果に対する次の操作（やり直す・微調整する・書き出す）が画面内で完結しているか
6. 破壊的操作に取り消しまたは確認があるか

### MagiClip 固有

- **主導線**（アップロード → 生成待ち → 結果確認 → 修正 → 書き出し）の現在地が画面上で分かるか
- **待ち時間**: 進捗の粒度・残り時間・完了の伝え方・その間にできることまで設計されているか
- **修正導線**: AI の出力が気に入らなかったときの逃げ道が、最短経路にあるか
- **比較**: 元素材と編集後を見比べられるか（AI が何を残し何を切ったか）

## 6. MagiClip の署名（ここだけは他と違う）

「シンプル」を徹底すると没個性になる。**個性は装飾ではなく、以下の 3 つの一貫した振る舞いで作る。**

### 署名 1: 魔法の瞬間（Magic Moment）

**完成した瞬間だけ**、ブランドの紫が現れる。ここが体験の頂点。

- 出す場所: 完成画面が開いた瞬間の、動画の周囲（細い紫の輪郭が一度だけ立ち上がって消える）
- 出してよい回数: **1 本の生成につき 1 回**。他の画面・他の操作では絶対に出さない
- 動きは 1 回・0.6 秒以内・イージングは減速のみ。点滅・回転・拡大縮小はしない
- ❌ NG: ボタンのホバー、読み込み中、保存完了などで同じ演出を使い回す（**使い回した時点で魔法ではなくなる**）

> 種明かしをしないこと。「魔法をかけています」と書くのではなく、**結果が出た瞬間に一度だけ光らせる**。

### 署名 2: 文字がタイムライン（Text as Timeline）

MagiClip の編集画面には、波形もトラックもクリップも置かない。**文字起こしの一覧そのものが編集対象**。

- 文字を消す → その区間の映像も消える
- 文字を直す → 字幕が直る
- 各行はサムネイル（その場面）とタイムコードを持つ。**映像は文字の添え物**という関係を崩さない
- この画面には、動画プレビューを「確認専用」として置く。編集は必ず文字側で行う

### 署名 3: 手数の可視化（Effortlessness）

「こんなに簡単だった」を体験の最後に残す。

- アップロードから完成までの操作数は **3 手以内**（選ぶ → 作成する → 待つ）を上限とし、増やす変更は原則却下する
- 迷わせる選択肢は、AI の既定値で埋めてから「変えたい人だけ変える」形にする
  （例: 書体は「AI におまかせ」が初期値。変えたい人だけ選ぶ）
- ❌ NG: 生成前に設定画面を挟む。確認ダイアログを増やす
